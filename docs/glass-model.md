# النموذج التقريبي للزجاج (نسخة 1)

نموذج رياضي تقريبي لتأثير Liquid Glass، مبني على البحث في
`reports/تأثير الزجاج السائل لدى أبل.md`. أبل لم تنشر أرقامها، لذلك:

- **[مصدر]** = قيمة أو معادلة مأخوذة من مصدر في البحث.
- **[اختيار]** = نقطة بداية اخترناها، تُضبط بالعين مقارنة بصور iPhone.

كل الأطوال بالبكسل المنطقي (logical px ≈ pt ≈ dp). في الشيدر تُضرب في `devicePixelRatio`.

---

## 0. الرموز

| الرمز | المعنى |
|---|---|
| `p` | موقع البكسل داخل الزجاج، والمركز عند (0,0) |
| `b` | نصف أبعاد الزجاج (نصف العرض، نصف الارتفاع) |
| `m` | الضلع الأقصر للزجاج = `min(2b.x, 2b.y)` |
| `r` | نصف قطر الزوايا (للكبسولة `r = m/2`) |
| `B(x)` | الخلفية **بعد الضبابية** عند النقطة x |
| `Y(c)` | السطوع = `0.213 R + 0.715 G + 0.072 B` **[مصدر: Prismal, Kyant0]** |

---

## 1. الانكسار والضبابية (النقطة الأولى: الأرقام)

### 1.1 الشكل: حقل المسافة (SDF)

```
sd(p) = length(max(|p| - b + r, 0)) + min(max(|p|.x - b.x + r, |p|.y - b.y + r), 0) - r
```

قيمته سالبة داخل الزجاج، وصفر على الحافة، وموجبة خارجه.

### 1.2 السماكة تزيد مع الحجم

أبل تقول إن الزجاج الأكبر "أسمك، وانكساره أوضح، وتبعثره أنعم" **[مصدر: WWDC25-219]**.
لذلك تُشتق كل القيم من `m`:

| المعامل | المعادلة | لشريط ارتفاعه 80 | المرجع |
|---|---|---|---|
| عرض شريط الحافة `h` | `clamp(0.30·m, 12, 32)` | 24 | أبل 20–30pt، و`boring.notch` 23pt، وKyant0 24dp **[مصدر]** |
| أقصى إزاحة `A` | `s · clamp(0.30·m, 6, 28)`، حيث `s` قوة يختارها المستخدم من 0 إلى 1.5 | 24 | Kyant0: tab bar `lens(24dp, 24dp)` **[مصدر]** |
| حد الإزاحة | `A ≤ 0.5·m` | — | Haze **[مصدر]** |
| الضبابية `σ` | `clamp(0.04·m, 2, 6)` | 3.2 | **[اختيار]**؛ Kyant0 يستخدم blur من 2 إلى 8dp |

### 1.3 الانحناء: ملف دائري، وأقوى ما يكون عند الحافة

```
t       = clamp(-sd / h, 0, 1)                 // 0 عند الحافة، 1 في نهاية الشريط
circle(x) = 1 - sqrt(1 - x²)
D(t)    = A · circle(1 - t)                    // = A عند الحافة، ثم 0 في الداخل
```
**[مصدر: Kyant0 circleMap]**. الوسط (`t = 1`) لا يتحرك أبدًا.

### 1.4 الاتجاه، والعيّنة من **خارج** الزجاج

```
n  = normalize(∇ sd_r'(p))        // يُحسب بنصف قطر منفوخ  r' = min(1.5·r, m/2)
p_s = p + n · D(t)                // العيّنة تُؤخذ للخارج، باتجاه الحافة
```

- نصف القطر المنفوخ `1.5·r` يمنع التجعّد في الزوايا **[مصدر: Kyant0]**.
- العيّنة للخارج لأن أبل تقول إن الزجاج "يأخذ عيّنات من مساحة أكبر منه" **[مصدر: WWDC25-323]**.
  ⚠️ الشيدر الحالي يأخذ العيّنة للداخل، وهذا عكس السلوك المطلوب.

### 1.5 اللون الأساسي

```
c0 = B(p_s)                                   // الضبابية قبل الانكسار، لا عيّنات frost
c1 = mix(vec3(Y(c0)), c0, V)                  // تقوية الألوان، V = 1.3
```
`V` يتراوح بين 1.28 (Prismal) و1.5 (Kyant0) **[مصدر]**. اخترنا 1.3 **[اختيار]**.

### 1.6 التشتت اللوني (اختياري، مطفأ في البداية)

```
R = B(p + n·D·(1 + δ)).r ,  G = c0.g ,  B = B(p + n·D·(1 - δ)).b ,   δ ≈ 0.04
```
يطبَّق على شريط الحافة فقط. إذا وقعت العيّنة خارج الشكل نرجع إلى G **[مصدر: Liquid]**.

## 2. التكيّف مع ما خلف الزجاج (النقطة الثانية)

ما تقوله أبل **[مصدر: WWDC25-219]**:
- الظل يقوى فوق النصوص ويضعف فوق الخلفيات الفاتحة السادة.
- اللون مدى من النغمات مربوط بسطوع المحتوى.
- العناصر الصغيرة تنقلب بين فاتح وداكن.

الأرقام في هذا القسم كلها **[اختيار]**؛ أبل لم تنشر عتبات.

### 2.1 قياس محلي داخل الشيدر (رخيص، لكل بكسل)

```
Yb   = Y(B(p))                                  // سطوع الخلفية المضبّبة
busy = clamp(4 · |Y(S(p)) - Yb|, 0, 1)          // S = الخلفية الحادة؛ الفرق = كثافة التفاصيل
```

`busy` يقيس "هل خلف الزجاج نص أو تفاصيل كثيرة؟". يحتاج عيّنة واحدة إضافية من الخلفية غير المضبّبة.

### 2.2 الظل الداخلي واللون المتكيّفان

```
shadowα = 0.06 + 0.14·busy - 0.06·Yb                 // يقوى فوق النص، ويضعف فوق الفاتح
inner   = shadowα · (1 - smoothstep(0, 0.5·h, -sd))²  // ظل داخلي قرب الحافة
tintα   = mix(0.10, 0.22, busy)                        // طبقة لون أكثف فوق التفاصيل
c2      = mix(c1, tintColor, tintα) · (1 - inner)
```

### 2.3 ضغط المدى (حتى يبقى المحتوى الأمامي مقروءًا)

```
c3 = Yt + (c2 - Yt) · 0.85         // Yt = 0.92 فاتح  /  0.18 داكن
```

### 2.4 قلب لون الأيقونات (فاتح ↔ داكن) مع تخلّف (hysteresis)

القرار على مستوى الويدجت، لا البكسل، فيُحسب في Dart:

```
Ȳ = متوسط سطوع الخلفية تحت الزجاج
foreground = داكن  إذا Ȳ > 0.62
foreground = فاتح  إذا Ȳ < 0.45
غير ذلك: يبقى كما هو               // التخلّف يمنع الوميض
```

كيف نحصل على `Ȳ` في Flutter؟ هناك خياران:
- **(أ)** من بيانات الواجهة نفسها، مثل لون القسم الذي تحت الشريط. هذا مجاني.
- **(ب)** لقطة صغيرة جدًا بـ `RepaintBoundary.toImage(pixelRatio: 1/16)` كل ~250ms. لها تكلفة، فتُطفأ في مستوى الأداء المنخفض.

الشيء الذي لا نستطيع تقليده تمامًا: أبل تقيس هذا داخل المُركِّب مجانًا، ونحن لا.

## 3. الاندماج والانفصال (Morphing) (النقطة الثالثة)

كل أشكال المجموعة تُرسم في **شيدر واحد** يجمع حقولها بـ smooth-min **[مصدر: Inigo Quilez]**.
هذا مقابل `GlassEffectContainer` عند أبل:

```
smin(a, b, k):  hk = max(k - |a - b|, 0) / k
                return min(a, b) - hk² · k / 4

sd = smin(sd_bar, sd_button, k)           // k = spacing ≈ 16–24 px  [اختيار]
```

- كلما كبر `k`، تبدأ الأشكال بالالتصاق من مسافة أبعد. هذا نفس معنى `spacing` عند أبل **[مصدر: توثيق SwiftUI]**.
- `n` يُحسب من تدرّج `sd` المدمج، بالفروق المركزية:
  `n ≈ normalize(sd(p+ε,·) - sd(p-ε,·), sd(·,p+ε) - sd(·,p-ε))`.
- حركة الذوبان = تحريك مركز الزر نحو الشريط، والمعادلة تتكفّل بالباقي.
- الظهور (materialize) = تحريك `A` من 0 إلى قيمتها خلال ~250ms **[اختيار]**.

## 4. اللمعات والحافة

أبل ترسم لمعتين بزاويتين متعاكستين، وحافة أغمق قليلًا في iOS 27 **[مصدر: هندسة عكسية + WWDC26]**.

```
rim   = 1 - smoothstep(0, w, -sd)                   // w = 1.5 px
L     = normalize(-1, -1)                            // ضوء ثابت أعلى اليسار
spec  = rim · (0.7·max(0, n·L) + 0.3·max(0, -n·L))   // key 0.7 / fill 0.3  [مصدر تقريبي]
dark  = 0.08 · (1 - smoothstep(0, 3, -sd))          // حافة داكنة خفيفة  [اختيار]
c4    = c3 · (1 - dark) + spec                       // اللمعة بالجمع
alpha = 1 - smoothstep(-0.75, 0.75, sd)              // تنعيم الحافة 1.5px  [مصدر: Liquid]
```

بدون جيروسكوب، لأن التقارير تقول إن أبل أزالته في iOS 27 (غير مؤكد رسميًا).

## 5. الأداء (النقطة الرابعة)

### 5.1 نموذج التكلفة

```
cost/frame ≈ N_bf · C_copy  +  C_blur(σ)  +  area · taps · C_tap
```

| الحد | ما نعرفه | المصدر |
|---|---|---|
| `C_copy` | كل `BackdropFilter` مستقل ≈ نسخة كاملة للشاشة، ~115 mW على Pixel 10 | liquid_glass_renderer **[مصدر]** |
| `N_bf` | `BackdropGroup` يجعل عدة فلاتر تدفع النسخة مرة واحدة (797 ← 688 mW) | **[مصدر]** |
| `C_blur` | σ ≤ 4 بكسل جهاز **أغلى**، لأن Impeller لا يصغّر الصورة | **[مصدر]** ← اجعل `σ·dpr > 4` |
| `taps` | الحالي 5 (frost) ← الجديد: 1، أو 2 مع `busy`، أو 4 مع التشتت | — |
| تصغير الالتقاط | 0.5 قلّل وقت الإطار ~40% على Pixel 6 (Haze) | **[مصدر]** |

### 5.2 مستويات الجودة

| المستوى | المحتوى | taps |
|---|---|---|
| **عالي** | ضبابية + انكسار + `busy` + تشتت + لمعات + دمج | 4 |
| **متوسط** (افتراضي) | ضبابية + انكسار + `busy` + لمعات + دمج | 2 |
| **منخفض** | ضبابية (σ أكبر) + لون ثابت + لمعة، **بدون شيدر** | 0 |
| **معتم** | Reduce Transparency / High Contrast | 0 |

### 5.3 الانتقال التلقائي بين المستويات

```
كل إطار: rasterMs من SchedulerBinding.addTimingsCallback
P90 على آخر 120 إطار:
  P90 > 0.75 · budget  لمدة 2 ثانية  ← انزل مستوى
  P90 < 0.40 · budget  لمدة 10 ثوانٍ  ← اصعد مستوى (مرة واحدة فقط لكل جلسة)
budget = 1000 / refreshRate  (16.7ms عند 60Hz، و8.3ms عند 120Hz)
```

العتبات **[اختيار]**.

## Q1. Native Android: libraries, backdrop capture, AGSL shader math, API levels, performance

### Takeaway
On Android, the strongest open implementations are Kyant0's **Backdrop** (formerly AndroidLiquidGlass), Chris Banes' **Haze 2.x `haze-glass`**, and FletchMcKee's **Liquid**. They all follow the same pattern. First, record the content behind the glass into a GraphicsLayer/RenderNode. Then run a `RenderEffect` chain (color filter → blur → AGSL `RuntimeShader` lens) clipped to a rounded-rect SDF. The lens displaces sample coordinates along the SDF gradient by `circleMap(1 - depth/height) * amount`, which is a spherical-cap height profile confined to an edge band. Finally, add highlights as a separate pass computed from `dot(sdfGradient, lightDir)`. RuntimeShader effects need API 33; plain blur needs API 31. Android 17 QPR (SDK "37.2") added a public `RenderNode.setBackdropRenderEffect`.

**Backdrop capture**
- Kyant0's `LayerBackdrop` records the background into a Compose `GraphicsLayer` (`rememberGraphicsLayer()`). When the glass draws, it translates by `-layerCoordinates.localPositionOf(glassCoordinates)` and calls `drawLayer(graphicsLayer)`, so the backdrop is re-drawn in the glass element's local coordinate space. A TODO in the code notes that "outer transformations lead to wrong position calculation". — [LayerBackdrop.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/backdrops/LayerBackdrop.kt)
- Kyant0 builds its effects with `RenderEffect.createChainEffect(new, previous)` (outer = the newly added effect). The lens uses `RenderEffect.createRuntimeShaderEffect(shader, "content")`. Chain order therefore follows call order, so `vibrancy(); blur(); lens()` means **color → blur → refraction**. — [internal/RenderEffect.kt (android)](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/androidMain/kotlin/com/kyant/backdrop/internal/RenderEffect.kt); [effects/RenderEffect.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/effects/RenderEffect.kt)
- Kyant0 grows the capture by a padding when blurring, so the blur can sample outside the shape (`if (radius > padding) padding = radius`). The lens then shrinks that padding by `refractionHeight`, and the shader receives `offset = -padding`. — [Blur.kt](https://github.com/Kyant0/AndroidLiquidGlass/tree/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/effects); [Lens.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/effects/Lens.kt)
- Haze ADR-0003 (2026-07-25): "On API 33 and newer, every supported Android Glass effect captures its source in one layer and feeds that capture into one retained output layer backed by a composed `RenderEffect` graph". The graph runs (1) separable blur kernels, with a native Gaussian for wide uniform blur, (2) sharp-to-blurred depth mixing, (3) one RuntimeShader for refraction, chromatic aberration, tint, tone, Fresnel and shape mask, and (4) a refraction-detail shader that samples the sharp source and is combined with premultiplied `Plus`. — [Haze ADR-0003](https://github.com/chrisbanes/haze/blob/98c833c/docs/adr/0003-use-one-android-fused-glass-renderer.md)
- Haze 2.x also has an experimental `HazeInput.Backdrop` mode. It samples "the combined earlier pixels in the same window surface" through a dedicated RenderNode, is gated on "the Android full 37.2 SDK version and hardware acceleration", is off by default (`HazeFeatureFlags.isPlatformBackdropEnabled = false`), and "has not established physical Android 17 (full SDK 37.2) acceptance or a performance result". — [Haze ADR-0010](https://github.com/chrisbanes/haze/blob/98c833c/docs/adr/0010-adopt-backdrop-as-the-adaptive-haze-input.md); [ADR-0009](https://github.com/chrisbanes/haze/blob/98c833c/docs/adr/0009-use-opt-in-android-window-backdrops.md)
- Haze reaches that platform hook by reflection: `RenderNode::class.java.getMethod("setBackdropRenderEffect", RenderEffect::class.java)`, gated on `Build.VERSION.SDK_INT_FULL`. — [HazeBackdropRenderer.android.kt](https://github.com/chrisbanes/haze/blob/98c833c/haze/src/androidMain/kotlin/dev/chrisbanes/haze/HazeBackdropRenderer.android.kt)

**API levels**
- `RenderEffect` and `createBlurEffect`, `createChainEffect`, `createColorFilterEffect`, `createBlendModeEffect` and `createShaderEffect` were added in API 31. `createRuntimeShaderEffect(RuntimeShader, String uniformShaderName)` was added in **API 33**. It "passes the contents of the RenderNode that this RenderEffect is installed on as an input to the shader". — [Android RenderEffect reference](https://developer.android.com/reference/android/graphics/RenderEffect)
- Kyant0 gates features with `isRenderEffectSupported() = SDK_INT >= S (31)` and `isRuntimeShaderSupported() = SDK_INT >= TIRAMISU (33)`, and the library's minSdk is 21. On API 31–32 the lens is skipped and only blur and color filters apply; below 31 nothing applies. — [Platform.kt (android)](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/androidMain/kotlin/com/kyant/backdrop/Platform.kt); [Lens.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/effects/Lens.kt)
- Haze: `isRuntimeShaderRenderEffectSupported() = SDK_INT >= 33`. Its glass fallback "blurs captured content on Android 12 and 12L", and API 30 and below get a translucent scrim (with RenderScript blur in the blur module). — [RuntimeShader.android.kt](https://github.com/chrisbanes/haze/blob/98c833c/haze-utils/src/androidMain/kotlin/dev/chrisbanes/haze/RuntimeShader.android.kt); [Haze CHANGELOG](https://github.com/chrisbanes/haze/blob/98c833c/CHANGELOG.md); [Haze docsearch](https://docsearch.algolia.com/mcp/docs/repo/chrisbanes/haze)

**AGSL shader math (Kyant0, verbatim core)**
- Rounded-rect SDF with per-corner radii, plus an analytic gradient: — [Shaders.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/internal/Shaders.kt)
  ```glsl
  float sdRoundedRect(float2 coord, float2 halfSize, float radius) {
      float2 cornerCoord = abs(coord) - (halfSize - float2(radius));
      float outside = length(max(cornerCoord, 0.0)) - radius;
      float inside = min(max(cornerCoord.x, cornerCoord.y), 0.0);
      return outside + inside; }
  float2 gradSdRoundedRect(float2 coord, float2 halfSize, float radius) {
      float2 cornerCoord = abs(coord) - (halfSize - float2(radius));
      if (cornerCoord.x >= 0.0 || cornerCoord.y >= 0.0)
          return sign(coord) * normalize(max(cornerCoord, 0.0));
      float gradX = step(cornerCoord.y, cornerCoord.x);
      return sign(coord) * float2(gradX, 1.0 - gradX); }
  ```
- Refraction lens. The height profile is a circular arc (spherical-cap bevel) restricted to a band of width `refractionHeight` inside the edge. The interior returns the unmodified sample (an early-out). The normal is computed with an *enlarged* corner radius (`min(radius*1.5, minHalf)`) so the displacement direction turns smoothly around corners. The optional `depthEffect` adds a radial component, and `refractionAmount` is passed in negated, so samples are pulled inward: — [Shaders.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/internal/Shaders.kt); [Lens.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/effects/Lens.kt)
  ```glsl
  float circleMap(float x) { return 1.0 - sqrt(1.0 - x * x); }
  float sd = sdRoundedRect(centeredCoord, halfSize, radius);
  if (-sd >= refractionHeight) return content.eval(coord);
  sd = min(sd, 0.0);
  float d = circleMap(1.0 - -sd / refractionHeight) * refractionAmount;
  float gradRadius = min(radius * 1.5, min(halfSize.x, halfSize.y));
  float2 grad = normalize(gradSdRoundedRect(centeredCoord, halfSize, gradRadius)
                          + depthEffect * normalize(centeredCoord));
  return content.eval(coord + d * grad);
  ```
- Dispersion: 7 taps (R, O, Y, G, C, B, P) along `d * grad * chromaticAberration * (x*y)/(hx*hy)`. The offset is therefore zero on the axes and largest in the corners. Each tap's channel is weighted (e.g. `r/3.5`, `b/3.0`) and alpha is averaged over the 7 taps. — [Shaders.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/internal/Shaders.kt)
- Highlight: a separate shader drawn with `BlendMode.Plus`. It uses the same SDF gradient, `intensity = pow(abs(dot(grad, float2(cos(angle), sin(angle)))), falloff)`, and the default is white at α=0.5, angle 45°, falloff 1. An "Ambient" variant uses `step(0, d)` so only one side lights. — [Shaders.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/internal/Shaders.kt); [HighlightStyle.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/highlight/HighlightStyle.kt)
- "Vibrancy" is a 4×5 color-matrix saturation boost of 1.5, using luma weights 0.213/0.715/0.072 and applied *before* the blur. — [ColorFilter.kt](https://github.com/Kyant0/AndroidLiquidGlass/tree/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/effects)
- Example parameters from the catalog: LiquidButton uses `vibrancy(); blur(2.dp); lens(12.dp, 24.dp)`. The bottom-tabs bar uses `blur(8.dp); lens(24.dp, 24.dp)`. The draggable tab "thumb" uses `lens(10.dp*progress, 14.dp*progress, chromaticAberration = true)`, so refraction animates in with press progress. Press feedback is a scale of `1 + 4.dp/height` (button) or `1 + 16.dp/width` (tabs). — [LiquidButton.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/app/src/commonMain/kotlin/com/kyant/backdrop/catalog/components/LiquidButton.kt); [LiquidBottomTabs.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/app/src/commonMain/kotlin/com/kyant/backdrop/catalog/components/LiquidBottomTabs.kt)

**AGSL shader math (FletchMcKee/liquid)**
- Liquid follows the same structure but works in coordinates normalized by `minDimension`. It uses the Inigo Quilez `sdgBox`-style SDF gradient with a 1.5× lens radius. The lens is `lensDepth = 1 - saturate(-sdf/refraction); distortion = 1 - sqrt(1 - lensDepth²); baseCoord = fragCoord + distortion * -curve * minDimension * sdfNormal`. — [LiquidShader.kt](https://github.com/FletchMcKee/liquid/blob/742108c/liquid/src/commonMain/kotlin/io/github/fletchmckee/liquid/internal/LiquidShader.kt)
- Dispersion is 3 taps with a cubic falloff: `aberration = dispersion * d³ * minDimension`, where `d = (frag-center)/size`. The red and blue taps are **rejected and fall back to green when the aberrated coordinate lands outside the shape SDF**, which prevents fringes that sample outside the shape. A comment notes "Cubic multiply is more efficient than pow()… pow() didn't work for screenshot tests". — [LiquidShader.kt](https://github.com/FletchMcKee/liquid/blob/742108c/liquid/src/commonMain/kotlin/io/github/fletchmckee/liquid/internal/LiquidShader.kt)
- Liquid has explicit edge anti-aliasing: `AA_WIDTH_PX = 1.5`, `aaAlpha = 1 - smoothstep(-aa/2, aa/2, sdf)`, with the output multiplied by aaAlpha (premultiplied). A comment notes "Using 1.5 softens jagged pixels around corners without softening the edge too much". If the refracted sample has α=0 it falls back to the unrefracted sample. Saturation and contrast are applied before the tint, so the user's tint is not itself saturated. The rim light is `smoothstep(-edge, 0, sdf) * abs(dot(n, (-0.15,-0.15)))`, added additively. — [LiquidShader.kt](https://github.com/FletchMcKee/liquid/blob/742108c/liquid/src/commonMain/kotlin/io/github/fletchmckee/liquid/internal/LiquidShader.kt)

**Shader math (Haze glass, the most elaborate)**
- Surface profiles are an enum: `Circle` (spherical dome), `Squircle` ("gentler flat-to-curve transition… smoother refraction gradients even when… stretched"), `Concave` (rays diverge), and `Lip` (convex rim plus concave center). — [SurfaceProfile.kt](https://github.com/chrisbanes/haze/blob/98c833c/haze-glass/src/commonMain/kotlin/dev/chrisbanes/haze/glass/SurfaceProfile.kt)
  ```glsl
  float circleMap(float x)   { return 1.0 - sqrt(max(0.0, 1.0 - x*x)); }
  float squircleMap(float t) { return 1.0 - smootherstep(t * sqrt(t)); }
  // Lip: mix(circleMap(x), -circleMap(x), smootherstep(clamp(t/0.7,0,1)))
  ```
  — [GlassShaders.kt](https://github.com/chrisbanes/haze/blob/98c833c/haze-glass/src/commonMain/kotlin/dev/chrisbanes/haze/glass/GlassShaders.kt)
- For elongated shapes (aspect ratio > 1.5) where the refraction band covers most of the half-size, Haze blends the edge-band distance toward a "dome" distance. That distance uses the normalized coordinate `n`: `r = sqrt(n.x²+n.y²-n.x²n.y²)`, with dome gradient `(n.x(1-n.y²), n.y(1-n.x²))`. This avoids a visible crease along the medial axis of capsules. Near the center the gradient is faded with `smootherstep(len/0.5)`, which avoids the unstable normalized direction there. — [GlassShaders.kt](https://github.com/chrisbanes/haze/blob/98c833c/haze-glass/src/commonMain/kotlin/dev/chrisbanes/haze/glass/GlassShaders.kt)
- Haze's "Edge" refraction profile, used by the built-in Regular and Clear styles, is an empirical fit with fast decay at the boundary: `t = dist/edgeWidth; profile = exp(-t/0.225) * (1-t²)²`. Magnitude is clamped to `min(strength*scale, minSide*0.5)`. Comment: "Empirical Clear fit: rapid boundary decay with a smooth finite-width cutoff." — [GlassShaders.kt](https://github.com/chrisbanes/haze/blob/98c833c/haze-glass/src/commonMain/kotlin/dev/chrisbanes/haze/glass/GlassShaders.kt)
- Default optics: Regular uses `refractionDisplacement = 48.dp`, `RefractionProfile.Edge(20.dp)` and `refractionHeightFraction = 0.15`. Clear uses `refractionStrength = 0.85`, `heightFraction = 0.35`, `displacement = 56.dp` and `Edge(28.dp)`. The constructor defaults are strength 0.7, heightFraction 0.25, displacement 15.dp and blurRadius 14.dp. — [GlassOptics.kt](https://github.com/chrisbanes/haze/blob/98c833c/haze-glass/src/commonMain/kotlin/dev/chrisbanes/haze/glass/GlassOptics.kt)
- Haze computes a Fresnel ambient term as `fresnelBase = 1 - max(dot(normal, (0,0,1)), 0); fresnel = fresnelBase^fresnelExponent` (cubed when the exponent is 3), and the rim shader has specular and rim-highlight uniforms. — [GlassShaders.kt](https://github.com/chrisbanes/haze/blob/98c833c/haze-glass/src/commonMain/kotlin/dev/chrisbanes/haze/glass/GlassShaders.kt)
- Continuous (superellipse) corners use a per-corner exponent, where `exponent > 2` is a superellipse and `== 2` is a circle. The distance is approximated by first-order normalization: `norm = (|a.x|^p + |a.y|^p)^(1/p); g = (a/norm)^(p-1); sd = (norm-1)*extent/|g|`. The same smoothed geometry drives the mask, refraction, lighting and rim. — [GlassShaders.kt](https://github.com/chrisbanes/haze/blob/98c833c/haze-glass/src/commonMain/kotlin/dev/chrisbanes/haze/glass/GlassShaders.kt); [Haze CHANGELOG](https://github.com/chrisbanes/haze/blob/98c833c/CHANGELOG.md)

**Performance on real devices (Haze is the only source with published numbers)**
- On a Pixel 6, a scene with 9 glass effects was "limited by Android RenderThread and Vulkan-driver work rather than Compose preparation or fragment area". Perfetto attributed the cost to "repeated layer traversal, `flush layers`, `flush commands`, and `Vulkan finish frame`", and lowering capture scale "did not materially improve" it. — [Haze ADR-0003](https://github.com/chrisbanes/haze/blob/98c833c/docs/adr/0003-use-one-android-fused-glass-renderer.md)
- Two alternatives were rejected. Android's built-in full-resolution blur and blend RenderEffects "increased `QueueSubmit`… enough to regress", and rasterizing the source each frame caused "repeated image allocation". Caching the base and compositing interaction patches gave 26.9 ms or 12.2 ms CPU P90. Compiling interaction into the fused shader gave 10.9 ms. — [Haze ADR-0003](https://github.com/chrisbanes/haze/blob/98c833c/docs/adr/0003-use-one-android-fused-glass-renderer.md)
- Input downscaling: on an animated 280×180dp glass workload on a Pixel 6, linear scale 0.75 measured 22.9 ms P50 / 30.1 ms P90 CPU, and 0.5 measured 13.8 / 19.5 ms. That is a 39.7% P50 reduction, with peak GPU memory down 30.7%. Haze picks a pixel fraction of 0.5 (linear ≈0.707) or 0.25 (linear 0.5) based on a pixel×update-cadence score with a threshold of 1.5M and a 12.5% hysteresis band. — [Haze ADR-0005](https://github.com/chrisbanes/haze/blob/98c833c/docs/adr/0005-use-cadence-weighted-adaptive-input-scaling-for-glass.md)
- On a Pixel 8a (Android 17, 60 Hz), merging two glass surfaces into one cluster "left about 4.6 ms less frame deadline margin at P90 and used about 14% more peak GPU memory". A dense grid of 40–45 glass members missed 60 Hz in both modes. — [Haze performance.md](https://github.com/chrisbanes/haze/blob/98c833c/docs/performance.md)
- A Kotlin Slack post calls Kyant0's alpha "relatively high performance", but gives no benchmark. — [kotlinlang Slack](https://slack-chats.kotlinlang.org/t/29486349/the-first-alpha-version-of-android-jetpack-compose-liquid-gl)

### Inferences
- The math that transfers most directly to a Flutter/Impeller fragment shader is: rounded-rect or superellipse SDF → band depth `t = clamp(-sd/h, 0, 1)` → height profile (`circleMap` or `squircleMap`, or Haze's `exp(-t/0.225)(1-t²)²`) → displacement along the SDF gradient computed with an inflated corner radius → `texture(backdrop, uv + disp/size)`. All of this is cheap per pixel and fits in a single fragment-shader pass.
- Haze's Pixel 6 finding (pass and submission count dominates, not fragment cost) suggests a Flutter implementation should minimize separate `BackdropFilter` / save-layer passes per glass element and merge blur, refraction, tint and rim into as few passes as possible. This is an inference from Android/Vulkan traces; Impeller's cost profile was not measured.
- The color → blur → refraction order used by Kyant0 and Haze (blur first, then sample the blurred texture with displaced UVs) avoids blurring the refraction warp itself. Haze additionally adds a *sharp* refraction-detail sample, which keeps edges crisp.

### Gaps
- I found no independent, published frame-time benchmarks for Kyant0 Backdrop or FletchMcKee Liquid on real devices.
- Neither the source nor the docs I could read give the exact first Android release of `RenderNode.setBackdropRenderEffect` beyond "version 37.2" (see Q4). I found no physical-device performance data for it either; Haze explicitly lists that as an open release gate.
- I did not read Haze's full blur kernels (`SemanticBlurKernel.kt`) or its rim shader in detail.

## Q2. Web: SVG displacement maps, browser limits, WebGL, physics write-ups

### Takeaway
The web has two families of implementation. (a) **SVG `feDisplacementMap` inside `backdrop-filter: url(#filter)`**: a JS-generated displacement-map image encodes per-pixel offsets in the R and G channels (128 = no offset), and `scale` sets the maximum pixel offset. This works with true backdrop sampling only in Chromium. (b) **WebGL/WebGPU** shaders that sample a snapshot of the page, which works cross-browser but has to capture the DOM itself. kube.io's widely cited article (September 2025) derives the displacement field from Snell's law with n≈1.5 over a "convex squircle" bezel.

### Cited Findings
- kube.io, "Liquid Glass in the Browser: Refraction with CSS and SVG" (September 2025) covers "Snell's Law, surface function modeling, displacement vector field generation, and SVG filter implementation" and is "currently Chrome-only due to SVG backdrop-filter limitations". — [daily.dev summary of kube.io](https://daily.dev/posts/liquid-glass-in-the-browser-refraction-with-css-and-svg-kube-io-9titwb303); original article: [kube.io/blog/liquid-glass-css-svg](https://kube.io/blog/liquid-glass-css-svg) (not directly readable from this session)
- Implementers summarize kube.io's model as a convex-squircle bezel, with a vertical ray refracted by Snell's law at n = 1.5 that continues to the back face, producing a sideways shift. One port reports 127 precomputed refraction samples, a numerical derivative with delta 0.001, and a normalized RG map (128 = zero), with the dynamically computed maximum displacement used as the SVG `scale`. These are that implementer's choices and may not match kube.io's stated values. — [solarisstudio PR #393](https://github.com/solarissongcontest/solarisstudio/pull/393); [PecoFence PR #9](https://github.com/DayuanJiang/PecoFence/pull/9)
- One npm package notes that its earlier displacement model "peaks at a 45° surface slope and falls to zero at the rim", and that the revised version "traces the actual ray through the slab". The physically traced version differs from naive slope-proportional displacement. — [@sohumsuthar/liquid-glass (npm)](https://www.npmjs.com/package/@sohumsuthar/liquid-glass)
- In plain displacement maps "light bends uniformly, ignoring Snell's Law", so the physics has to be baked into the map in JS. — [DEV: maxgeris](https://dev.to/maxgeris/recreating-apples-liquid-glass-effect-on-the-web-with-css-svg-and-physics-based-refraction-5cek) (search snippet only)
- Shu Ding's liquid-glass (June 2025) generates the map on a canvas. A `fragment(uv)` function returns the *source UV* to sample, and the map stores `dx = pos.x*w - x`. Values are normalized by `maxScale = 0.5*max|d|`, written as `r = dx/maxScale + 0.5` (×255), and `feDisplacementMap scale = maxScale/dpi` is set with `xChannelSelector=R`, `yChannelSelector=G`. The CSS is `backdrop-filter: url(#id_filter) blur(0.25px) contrast(1.2) brightness(1.05) saturate(1.1)`. The demo's lens is `displacement = smoothStep(0.8, 0, sdf - 0.15); uv' = (uv-0.5)*smoothStep(0,1,displacement)+0.5`, which magnifies toward the edge. — [shuding/liquid-glass liquid-glass.js](https://github.com/shuding/liquid-glass/blob/a2d2e84/liquid-glass.js)
- rdev/liquid-glass-react: "Safari and Firefox only partially support the effect (displacement will not be visible)"; it also supports configurable chromatic aberration. — [rdev/liquid-glass-react README](https://github.com/rdev/liquid-glass-react/blob/ac48eab/README.md)
- Browser support for `backdrop-filter: url()`: WebKit bug 245510 (opened 2022) is still tracked, with a patch described in June 2026 whose landing is unconfirmed. WebKit 313914 (May 2026) says the foreignObject + feDisplacementMap approach works in Chrome and Firefox but not Safari, and that `backdrop-filter` works only in Chrome for this technique. A Mozilla Connect idea asks for SVG filters in `backdrop-filter`, and Mozilla bug 1961378 (backdrop-filter ignored on the blob-image fallback, as with some SVG url filters) is open. Firefox bug 1868479, a regression in FF 120, was fixed in FF 121, so the Firefox picture is contradictory. — [WebKit 245510](https://bugs.webkit.org/show_bug.cgi?id=245510); [WebKit 313914](https://bugs.webkit.org/show_bug.cgi?id=313914); [Mozilla Connect](https://connect.mozilla.org/t5/ideas/support-svg-filters-in-backdrop-filter-for-advanced-glass/idi-p/98453); [Bugzilla 1961378](https://bugzilla.mozilla.org/show_bug.cgi?id=1961378); [Bugzilla 1868479](https://bugzilla.mozilla.org/show_bug.cgi?id=1868479)
- WebGL/WebGPU: liquidGL v3 renders with "WebGPU… with an automatic fallback chain of WebGPU → WebGL2 → WebGL1 → CSS `backdrop-filter`". To get around WebGL's inability to read live screen pixels it uses an "offscreen rendering technique" (a page snapshot texture sampled at `(point - snapshot.xy)/snapshot.zw`). Its feature table lists CSS-animation refraction as **unsupported**. Its chromatic aberration "disperses the red and blue channels either side of the refraction vector, blue displaced further than red". — [naughtyduk/liquidGL README](https://github.com/naughtyduk/liquidGL/blob/88f681a/README.md); [liquidGL.js](https://github.com/naughtyduk/liquidGL/blob/88f681a/scripts/liquidGL.js)

### Inferences
- The SVG pipeline amounts to "precompute a displacement texture from SDF plus height profile, then do one dependent texture fetch". On Flutter, the equivalent is either evaluating the SDF analytically in the fragment shader (as the Android libraries do) or baking an RG16F displacement texture once per shape size. The analytic route avoids 8-bit quantization (the 128-neutral encoding gives only about ±127 steps of `scale`) and avoids rebaking on resize.
- Normalizing by the maximum displacement and passing it as `scale` is the same idea as a `refractionAmount` uniform: the shape and the magnitude are decoupled.

## Q3. Common mistakes that make the effect look bad, and how good implementations avoid them

### Takeaway
Good implementations confine displacement to an edge band with a smooth profile. They compute normals with an inflated corner radius or dome blend so the warp does not crease. They pad or clamp captures so samples never fall outside the texture, and reject dispersion taps that land outside the shape. They anti-alias the SDF edge over about 1.5 px, apply blur before refraction, and add a separate additive rim/specular pass.

### Cited Findings
- **Sampling outside the capture or texture.** Kyant0 pads the backdrop capture by the blur radius and keeps `TileMode.Clamp`. Haze found its custom blur's "clipped sampling bounds… leaving a sharp frame around the material" and switched wide blur to a native Gaussian node. A Haze changelog entry also fixed blur that "leak[ed] transparent pixels along edges when its captured input is downscaled". — [Kyant0 Blur.kt](https://github.com/Kyant0/AndroidLiquidGlass/tree/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/effects); [Haze ADR-0003](https://github.com/chrisbanes/haze/blob/98c833c/docs/adr/0003-use-one-android-fused-glass-renderer.md); [Haze CHANGELOG](https://github.com/chrisbanes/haze/blob/98c833c/CHANGELOG.md)
- **Transparent or edge samples after refraction.** Liquid re-samples the unrefracted coordinate when `fragColor.a <= 0`, and drops R/B dispersion taps whose coordinates fall outside the SDF. — [LiquidShader.kt](https://github.com/FletchMcKee/liquid/blob/742108c/liquid/src/commonMain/kotlin/io/github/fletchmckee/liquid/internal/LiquidShader.kt)
- A gamedev.net article on screen-space refraction recommends fading displacement near the frame boundary and rejecting out-of-range footprints, so clamped edge texels do not smear. — [gamedev.net screen space refraction](https://gamedev.net/shaderlab/52-screen-space-refraction/) (search snippet)
- **No edge anti-aliasing.** Liquid uses a 1.5 px smoothstep on the SDF and outputs premultiplied color. A Haze changelog fix stopped "the layer beneath show[ing] through the straight edges of its surfaces". An HN commenter reported "high contrast single-pixel width artifacts at the edges" of an SVG demo. — [LiquidShader.kt](https://github.com/FletchMcKee/liquid/blob/742108c/liquid/src/commonMain/kotlin/io/github/fletchmckee/liquid/internal/LiquidShader.kt); [Haze CHANGELOG](https://github.com/chrisbanes/haze/blob/98c833c/CHANGELOG.md); [hn.svelte.dev item 45174297](https://hn.svelte.dev/item/45174297)
- **Creases and discontinuities in the warp.** Kyant0 computes the gradient with `min(radius*1.5, minHalf)` instead of the actual radius, and Liquid does the same (`lensVr = min(shapeVr*1.5, ...)`). Haze blends to a dome field for elongated shapes and fades the gradient near the center (`smootherstep(len/0.5)`). Haze's Squircle profile is described as giving "smoother refraction gradients even when the shape is stretched". — [Kyant0 Shaders.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/internal/Shaders.kt); [LiquidShader.kt](https://github.com/FletchMcKee/liquid/blob/742108c/liquid/src/commonMain/kotlin/io/github/fletchmckee/liquid/internal/LiquidShader.kt); [Haze GlassShaders.kt](https://github.com/chrisbanes/haze/blob/98c833c/haze-glass/src/commonMain/kotlin/dev/chrisbanes/haze/glass/GlassShaders.kt); [SurfaceProfile.kt](https://github.com/chrisbanes/haze/blob/98c833c/haze-glass/src/commonMain/kotlin/dev/chrisbanes/haze/glass/SurfaceProfile.kt)
- **Too-strong or uniform displacement.** Every library confines refraction to a band (Kyant0: early-out when `-sd >= refractionHeight`; Haze: displacement clamped to `minSide*0.5`, plus an Edge profile with exponential decay). A WebGL write-up notes "the center stays calmer, while the edges distort the scene more strongly". — [Kyant0 Shaders.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/internal/Shaders.kt); [Haze GlassShaders.kt](https://github.com/chrisbanes/haze/blob/98c833c/haze-glass/src/commonMain/kotlin/dev/chrisbanes/haze/glass/GlassShaders.kt); [DEV: where WebGL meets liquid glass](https://dev.to/_carson_ye_/where-webgl-meets-liquid-glass-401l) (search snippet)
- **Ghosting and lagging backdrops.** WebGL implementations warn of "artifact formation due to asynchronous updates between WebGL and the DOM", and liquidGL cannot refract CSS animations. On Android, Haze fixed "stale content while scrolling on API 31" and stale RenderScript captures. — [DEV: maxgeris WebGL library](https://dev.to/maxgeris/webgl-based-javascript-library-for-pixel-perfect-ios-liquid-glass-effect-with-refractions-and-3p8m) (search snippet); [liquidGL README](https://github.com/naughtyduk/liquidGL/blob/88f681a/README.md); [Haze CHANGELOG](https://github.com/chrisbanes/haze/blob/98c833c/CHANGELOG.md)
- **Dispersion fringes reading as ghost images.** Kyant0 weights dispersion by `(x*y)/(hx*hy)` (zero on the axes) and enables it only on the small pressed "thumb". Liquid uses a cubic falloff from the center. — [Kyant0 Shaders.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/internal/Shaders.kt); [LiquidBottomTabs.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/app/src/commonMain/kotlin/com/kyant/backdrop/catalog/components/LiquidBottomTabs.kt); [LiquidShader.kt](https://github.com/FletchMcKee/liquid/blob/742108c/liquid/src/commonMain/kotlin/io/github/fletchmckee/liquid/internal/LiquidShader.kt)
- **Wrong coordinate space.** Kyant0 notes in the code that outer transforms break `localPositionOf` and falls back to window-position deltas. Haze fixed sampling across sibling `ComposeView`s and alignment across desktop windows. — [LayerBackdrop.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/backdrops/LayerBackdrop.kt); [Haze CHANGELOG](https://github.com/chrisbanes/haze/blob/98c833c/CHANGELOG.md)
- **Missing highlights or wrong ordering.** Highlights are drawn as a separate additive (`BlendMode.Plus`) pass in Kyant0 and as a separate rim/foreground pass in Haze. Liquid applies the tint *after* saturation and contrast, so the user's tint is not boosted. — [HighlightStyle.kt](https://github.com/Kyant0/AndroidLiquidGlass/blob/eb4a0ea/backdrop/src/commonMain/kotlin/com/kyant/backdrop/highlight/HighlightStyle.kt); [Haze ADR-0003](https://github.com/chrisbanes/haze/blob/98c833c/docs/adr/0003-use-one-android-fused-glass-renderer.md); [LiquidShader.kt](https://github.com/FletchMcKee/liquid/blob/742108c/liquid/src/commonMain/kotlin/io/github/fletchmckee/liquid/internal/LiquidShader.kt)
- **Blur cost.** A Figma user found that hiding the "Blur" layer in iOS 26 kit glass fixed slow transitions. — [Figma forum](https://forum.figma.com/report-a-problem-6/mirrored-prototype-using-apples-ios26-ui-kit-is-really-slow-and-drains-the-battery-43692)

### Inferences
- Multi-tap blur ghosting typically comes from too few, too widely spaced taps. Haze avoids it with separable semantic kernels plus a native Gaussian for wide radii, and Kyant0 avoids it by using the platform blur rather than an in-shader multi-tap blur. On Flutter, using `ImageFilter.blur` (which runs as an Impeller Gaussian) before the refraction shader is analogous, and is preferable to looping taps inside the fragment shader.
- Using `pow()` with integer exponents has caused test or determinism issues (Liquid). Explicit multiplies are safer in mobile shader compilers.

### Gaps
- I found no systematic study or official guideline listing liquid-glass failure modes. The list above is assembled from code comments, changelogs and search snippets.

## Q4. Google / Android official equivalent or response (as of Nov 2026)

### Takeaway
Google has not shipped a Liquid Glass equivalent component for apps. Android 16 / Material 3 Expressive introduced system-UI background blur (notification shade and Quick Settings, starting in QPR1), along with a user toggle to disable it. Android 17 is reported to use more blur. The notable developer-facing addition is the public `RenderNode.setBackdropRenderEffect(RenderEffect)`, documented as "Added in version 37.2", which lets a node filter whatever is already drawn behind it.

### Cited Findings
- `RenderNode.setBackdropRenderEffect(RenderEffect)`: "Configure the RenderEffect to apply to the backdrop contents of this RenderNode… if `createBlurEffect` is provided, the previous content behind this RenderNode will be blurred before the RenderNode is drawn in to the destination". The reference page lists it as "Added in version 37.2". — [Android RenderNode reference](https://developer.android.com/reference/android/graphics/RenderNode)
- Earlier AOSP commits by Dongya Jiang added `setBackdropRenderEffect` for View and RenderNode as `@hide`. — [AOSP mirror commit (omnirom)](https://gerrit.omnirom.org/plugins/gitiles/android_frameworks_base/+/e2b9938b7d02c420434fdea77aaf7cdb832d4460%5E%21); [/e/OS mirror](https://gitlab.e.foundation/e/os/android_frameworks_base/-/commit/e93a68ed710c10db187eac296b23b5f8483c5674)
- Haze uses this API, gated on SDK_INT_FULL 37.2 and behind an off-by-default flag, and states it is unvalidated on physical Android 17 devices. — [Haze ADR-0010](https://github.com/chrisbanes/haze/blob/98c833c/docs/adr/0010-adopt-backdrop-as-the-adaptive-haze-input.md)
- Android 16 introduced background blur as part of Material 3 Expressive. Android 16 QPR1 brought blur first to the notification and Quick Settings panels. Google framed its blur as minimizing distraction and focusing attention, as opposed to Apple's approach, and press coverage calls it "more subtle" than Liquid Glass. — [heise: Android 16 QPR1 first look](https://heise.de/-10399974); [9to5Google](https://9to5google.com/2025/06/15/android-16-debut-boring-ios-26/); [GSMArena](https://www.gsmarena.com/google_previews_android_16_and_wear_os_6s_material_3_expressive_look-news-67771.php)
- Google confirmed a setting to turn off background blur. Android Authority notes this helps accessibility and can slightly improve battery life. — [Android Authority](https://www.androidauthority.com/android-getting-option-disable-background-blur-3590124)
- Reporting says Android 17 introduces "significantly more blur" but "don't call it Liquid Glass". — [Tom's Guide](https://www.tomsguide.com/phones/android-phones/googles-next-android-update-may-take-inspiration-from-apple-but-dont-call-it-liquid-glass) (search snippet only; page not readable from this session)

### Inferences
- Because Android users can disable blur system-wide, and Haze honors "reduced-transparency preferences", a Flutter implementation on Android should probably check accessibility and transparency settings and degrade to a frosted or opaque fallback.
- `setBackdropRenderEffect` is a platform View/RenderNode API. Flutter renders into its own surface, so it would not directly help a Flutter app; Flutter still has to capture and refract its own layer tree (via `BackdropFilter` / `ImageFilter.shader` in Impeller).

### Gaps
- No Material 3 / Jetpack Compose component that implements glass refraction officially was found.
- I could not confirm from primary Google sources which public Android 17 release first shipped SDK 37.2, or whether `View.setBackdropRenderEffect` is also public.
- I found no Google statement specifically responding to Liquid Glass beyond the press quotes summarized above.
